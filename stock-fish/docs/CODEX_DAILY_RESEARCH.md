# Codex日常研究协议

日常用户入口为[使用说明](../../USER_GUIDE.md)，运行维护见[部署说明](../../DEPLOYMENT.md)，当前未达标项目见[当前状态](../../CURRENT_STATUS.md)。本协议用于调用已有逻辑；详细规则与架构按[技术索引](README.md)展开。

## 每次执行

1. 核对真实实例、配置地址、DB/state、交易日历与保存运行。查询实际地址的健康和轻量状态；只读请求不调用可能改变计划或epoch的维护入口。
2. 说明目标交易日、实际观察日、资料截止、生成时间、来源可见时点、范围和run_id。“明天”按上海日期与正式交易所日历解释，日历越界不猜节假日。
3. 优先复用同一保存运行、详情、正式导出及既有私有报告。历史查询保留原实现/配置/源身份，不给旧榜换日期，不用今天规则重算冒充昨天。
4. 需要新资料时核对授权、预算和在途任务，只执行一次有界续采/计算；响应不明先查job，不盲目重发。成功、资料齐备、实际激活分别报告；缺少来源不造合法EMPTY。
5. 日常primary只调用active V2的DAILY_PRIMARY_FAST；PV沿用已确认实验上下文。只有明确的多策略对照或深度研究走RESEARCH_FULL。DAILY_V1独立报告可用性。
   明确选择短线强势版本时，使用已登记的 `SHORT_HORIZON_STRENGTH_R1` 单策略研究入口，沿用原实验作业、保存运行和导出体系，不重跑默认多策略套件。观察选择与正式FOCUS独立；新规则回算旧日期必须标为事后研究。规格见[短线强势R1](SHORT_HORIZON_STRENGTH_R1.md)。
   本次用户明确授权的R2研究采用 `SHORT_HORIZON_STRENGTH_R2`，规格见[R2](SHORT_HORIZON_STRENGTH_R2.md)。有真实保存R1而其原历史库不可读时，可显式调用薄封装 `short-horizon-r2 --help`：核验原文件SHA及完整canonical run、原输入和资格，保留R1父数值；新参与度只取原inline资料，金额/题材另附来源能力，另存新的私有产物，不登记业务库或新建名单库。原历史库未重验必须写明。后续当前盘前可采用较新的真实context cutoff，原父cutoff及价格资格不得改写。
   目标交易日采用原字节认证的完整日历核对，不按周一至周五猜测。`TARGET_SESSION_CALENDAR_CONTEXT_V1`将目标日期、实际收件时点和日历父证据绑定新run；同一时点的冲突日历拒绝。日历normalizer原`event_time`代表请求覆盖截止日；仅已识别的日历元数据按发布时间/实收/入库时钟判断可见，保留原未来覆盖时间及专属语义，不放宽任何行情或风险的四时钟门禁。旧cutoff缺后续日历时保持UNKNOWN，不用后来日历补入旧run。
6. 从同一run读取全部/焦点数量、解释、JSON/CSV导出与后验；聊天可节选，完整保存结果不截断、不凑数。未成熟或缺失后验保留null。
   对完整保存R2采用[完整交付V2](SAVED_R2_COMPLETE_DELIVERY_V2.md)的薄封装 `deliver-saved-r2`：严格绑定原run/input/原策略身份和完整资格池，核对真实RAW、receipt及result；重新发行当次题材情境，再附经济方向和全文展示。原selector不运行，正式全部/观察/焦点/未选导出保留；来源缺口不删原观察股，按模型或UNKNOWN完整交付。新解释先入NON_DELIVERY_AUDIT；精确派生归档状态错误只有在原来源及实现复核通过后才回退为完整原模型名单，新解释仍UNKNOWN，其他内容、身份和时间错误保持拒绝。DATED_ONLY与显式CURRENT_COHORT_BACKVIEW分列，缺会话不压缩窗口。历史原选择截止、新情境/业务截止、生成和展示时间各自保存；早于原run可见时点只输出不可见状态，不泄露候选。普通JSON声明不能恢复来源能力。每次使用新的私有目录，执行预算与在途任务另核对，不能把工程通过或已保存旧附件当作当日无人值守成功。
   本次完整清单与题材研究报告均聚焦主线：有经过原始来源认证的当日活跃依据、与冻结合格候选相交、并有独立当日主线范围证据。电池漏报审计后采用[呈现V4](THEME_OBSERVATION_DIAGNOSTICS_V1.md)：原两日确认且仍走强/发酵的列为确认主线；首日原候选条件PASS的单列“发酵观察，尚未确认”；原候选与两日确认仍PASS而阶段DIVERGENCE的另列“活跃主线，出现分歧”，不隐藏也不重标走强。来源诊断中的全部PENDING标签不得自动展开为用户主线，同方向归并保留原来源，风险分列。没有题材来源或观察日题材证据时必须显著提示主线识别不可用。供应商目录/成员完整性不代表经济题材及时覆盖；主题归属遗漏与真实无关系分开。股票选择及全部题材原数值不改，旧run、版本身份和必要审计证据保留；退役V2/V3展示报告及副本按本轮引用和活动依赖核对后清理。不设置新的50/100亿元概念硬门槛，不按旧阶段标签或单一正收益认定活跃。题材弱、混合或合力未成立的合格个股归模型；未知另列。非主线仅作为解释主线资金轮动的必要背景。年内主线资格必须按当时业务日数据及登记规则逐日核验；当前成分或当前候选回看明确标注选择偏差，不能当历史主线全覆盖或过去盘前预测。
   若日期化真实RAW及物理receipt仍在而旧result包装缺失，采用显式[完整流式交付V3](SAVED_R2_COMPLETE_STREAM_DELIVERY_V3.md) `deliver-saved-r2-stream` 和 `SAVED_R2_DELIVERY_SOURCES_V2`。完整原件与回执、原四钟、真实整行数和请求范围分别验真，不补造result。由本次reader发行真实market stream，请求原完整calendar最后67会话，缺日不压缩；旧V1/V2合同不放宽。journal和全部投影共用512MiB输出预算，执行wrapper须在producer期间实时观测。真实新发行、归档读取、原名单、历史PIT和连续调度各自验收；当次失败不自动重试或扩大额度。
7. 跟踪更新原run，需要合法后续输入才追加标签/修订；原排序与原信号不覆写。Codex解释和未知另列。
8. 私有报告保存在被Git忽略的reports/codex/，响应注明run_id、路径、覆盖和阻塞。普通研究不创建空提交或公开行情。

核心与独立附件分阶段生成时，各阶段须有自己的完整保存及终验依据。整体执行后来失败不得写PASS；已经独立核准的原核心可在正式导出字节、完整集合、原截止和来源边界再次核对后交付，失败附件保持UNKNOWN/未生成。原日历窗口和预算不扩大，运行到最后日期也不等于全部指标或封存完成；新执行版本应把预算异常与证据格式异常分开传播，并分别保存主失败、清理及控制持久化结果。原失败记录不追改。

显式[主题流V2](THEME_EVOLUTION_STREAMING_V2.md)已通过独立96项夹具验收，联合收尾使用真实V2 journal，保持原数学与完整日历。真实I/O失败不能降为证据格式UNKNOWN，live callback也不能替代外层整原件SHA/7FP与当前owner。默认CLI、旧caller和服务尚未切换；保存核心接新附件须使用另登记的真实执行版本，完整认证原run/input和五份正式导出、不再运行selector或normalizer，保留原截止和原theme UNKNOWN，新情境使用实际新截止。夹具、生产端终验、归档只读审阅与每日全链路成功分别记账，不因夹具通过自动重跑旧失败或提高预算。

本次明确授权的年度自主复盘按[主线周期标准V1](MAINLINE_CYCLE_RESEARCH_STANDARD_V1.md)执行，无需用户逐轮审查。报道催化、梯队、分歧先保留原件及实际时钟，再与不同原创家族和逐日事实互证；同稿转载/同上游不增加独立证据数。计数、单位、成交范围及时间冲突保留未知。月份季度与孤立节点不认证情绪周期；新规则在不同周期验证，不能把今天抓到的旧报道补成旧盘前可见。普通每日任务仍不自动调参或提交。

年度正文统一维护[2026年以来短线总报告](2026_SHORT_TERM_MAINLINE_REPORT.md)，新事实和反证并入对应章节，不再制作多个阶段PDF。已保存明确WATCH集合的留存与包含UNKNOWN的完整机会状态指标分开；集团项目催化不能直接归为上市公司实际业务。用户本轮已授权工程收尾清理与指定main同步，普通日常任务仍不自动删除数据库、改源码或提交。

变化趋势依该标准单列资金、参与、集中、持续、相对市场及席位事实和反证，不能把当前篮子交易家数说成历史规则合格家数。新增[报道事件V1](THEME_EVENT_EVIDENCE_V1.md)尚未接每日默认run/export；使用时必须认证真实原件及原生父/冻结选择，不接受普通自hash JSON授权，不据新闻加名单或升级FOCUS。

取得CLS原件但缺作者时可显式调用独立[可选署名解析V2](CLS_NEXT_DATA_OPTIONAL_BYLINE_V2.md)，不能改写旧V1解析失败或旧run。新原件能力重读SHA/receipt和真实捕获时钟，日期由连续原文上下文证明；缺旧ingestion须登记本次真实再摄入，不补造历史时刻。姓名、明确题材归因、同日身份与原生资格分层相交，连板榜具名不自动成为主线成员。每日名单变化另拆留存、新增、退出、同股量价与边界截断持续时间；这些事实不直接修改门槛、评分或FOCUS。默认服务尚未自动接线。

[席位原件V1](LHB_SEAT_EVIDENCE_V1.md)须认证实际归档manifest及全部原件，再恢复提供方编码；买卖榜重复appearance不当独立游资，无编码机构不按同名合并、渠道不推定自然人。单位/披露窗/独立发布时间未知时reported数值不用于FUNDS评分。新捕获附件按新cutoff绑定冻结原生父与选择，不能回填原run；当前默认入口尚未接线。同期指数明确代码、覆盖/权重、原字段基准及实际收件时间，与四板等权市场参考分列，历史SDK下载不冒充历史身份或PIT证明；指数金额不跨覆盖求和。

历史换手资料采用显式新[重建适配V1](HISTORICAL_REPLAY_TURNOVER_V1.md)，保持冻结base认证且仅同父RAW补turn。使用时保存新input及新audit身份，保留原实际时钟、资格、复权和未知；仅inline，默认入口/DB未接线。全市场交易/上涨家数与规则合格家数分列，扩展RAW范围不自动授予历史资格。资金变化须结合价格广度和集中度；主线相对市场优势下降与自身广度下降分别解释。近5日软参考含观察日、前20日描述基准排除观察日，不跨定义补点；新联合假设须留账且经独立周期检验才接预测配置。

[市场事实V1](MARKET_DESCRIPTIVE_CONTEXT_V1.md)须显式传入真实原生market stream能力与新产物目录，不能由保存JSON重启来源权限。输出保存全RAW分段审计、逐轴UNKNOWN、真实相邻会话与排除T的prior20；验证同时锁定发行时来源/文件registry，并在产物核验后重新读消费原件。它未接默认run/export或题材composer，不将四板总体称为历史合格池，不凭事实序列或工程通过添加预测分数。

[市场解释V1](MARKET_EXPLANATION_V1.md)经 `market-explanation` 显式认证原始来源、重新发行原生事实能力并绑定已保存run，另存新附件；receipt/map JSON仅定位原件，不恢复旧capability。`report --market-explanation` 和 `daily-report --market-explanation` 只读展示同run/input/观察日附件，保持原结果、CSV和快照hash。显示截止必须覆盖原件四时钟、情境截止和附件实际生成时间；晚到资料不能回填旧盘前。完整1/3/5会话的变化与斜率只作描述反证，无主题成员/合格范围时不得升格为主线或情绪周期。默认服务尚未自动采纳附件，日常协调要明确记录调用和UNKNOWN。

[同股参与变化V1](COHORT_PARTICIPATION_TRENDS_V1.md)仅作显式研究数学层：调用方先核验保存 run 全文、全部 eligible 行、同日身份、规则及实际来源时钟，再构造完整声明，按真实交易日历调用。未知资格和已知排除的原因另存，不能把池外当形态退出。共同 eligible 同股比较留存、新增、退出与 Jaccard；固定篮子金额与每日变化成员的名单金额分列，不把后者变化当同股扩张或净流入。缺整日、未知决策、资格迁移、规则变化和首尾覆盖分别截断观察段；跨缺日端点不能称连续留存或完整周期。多个固定题材篮子若重叠，调用方仍须先另证并处理共享成员，不能把各篮子金额相加当独立吸金。该组件不认证输入声明，不读 DB/网络、不运行 selector，尚未接默认 CLI、每日服务或预测权重；工程通过与实样本数学通过分别报告。

## 调用入口

用户已授权脱离Codex的单命令流程工程。[独立终端入口V1](STANDALONE_PREMARKET_WORKFLOW_V1.md)为 `python scripts/stockfish.py premarket --theme-read-gib 12 --max-requests 768 --max-seconds 0`（业务目录及既有项目环境）。新命令不先查Web健康、不构造业务DB，直接认证原件缓存、按日历补缺、调用原R2、完整67日题材及最后3亿元展示；原选择和五导出保留，阶段失败与UNKNOWN分列。新profile各阶段预算显式登记，不从某次聊天授权继承，也不自动扩容/重试。它未替换现有服务的SAM V2、下表API或聊天heartbeat，真实新入口冷/暖启动与连续交付另验收。Codex可调用同一命令，不再需要在聊天中手工拼接私有日报脚本。

[压缩证据日志V3](EVIDENCE_AUDIT_SPOOL_V3.md)和[主题执行原型V3](THEME_EVOLUTION_STREAMING_V3.md)目前仅用于显式工程诊断，未选作真实日报后端，也没有改接下表或完整流式交付V3命令。完整数学等价的同67会话夹具中，总实际返回反而由V2的1,620,240升至V3的1,910,591字节；压缩输出较小不能判资源就绪。真实完整来源、原run/input、五导出、完整日历及外层终验合同保持，资源上界未知时不自动真实重跑或扩大预算。

Python使用[scripts/codex_research.py](../scripts/codex_research.py)薄封装和既有API；参数以实际--help为准，地址从本次核验取得。全局--base-url/--env-file/--timeout放在子命令前。Key仅经既有私有配置传入，不放命令行或日志。

| 请求 | 已有入口 |
|---|---|
| 状态、配置、运行列表 | status / rules / list |
| 原run详情和正式导出 | detail RUN_ID SECURITY / export RUN_ID / report RUN_ID |
| 查询每日交付与后验 | daily-report / daily-outcomes / daily-observation |
| 已确认研究或合法更新 | select / run / capture / track；执行前区分只读与写入 |

封装不复制策略、不另建库、不自动切换运行服务。当前Go候选命令与写入边界见[终端说明](../../stock-fish-go/delivery/USER_GUIDE.md)，不把Python实例与Go隔离实例混作同一部署。

## 规则、资料与权限

主动核心保持[STAGE_AWARE_MOMENTUM_V2](STAGE_AWARE_MOMENTUM_V2.md)，V1为历史只读兼容，R1为显式研究；公式/配置及旧结果保留。先核验证券身份、业务日和父来源时点，再使用价格、题材、资金或风险。未知不当FALSE，缺结果不计零收益，资料不足不称正式FOCUS。

源码、模型、已计划的20个会话和历史下载均不证明当前数据就绪或连续使用可靠。MARKET_EDGE=NOT_ESTABLISHED；DAILY_RECOMMENDATION_SCORE_V1仅读后验，不自动调参。

普通名单、日报、查询和跟踪不自动授权改生产代码/正式策略、提交推送、购买服务、升级模型、扩大预算或部署切换。沿用用户当前模型；无需新增应用内LLM凭据。经明确授权的工程交付按[AGENTS](../../AGENTS.md)和[工程约定](../../ENGINEERING_BASELINE.md)检查、中文提交并推送，不扩大到后续普通研究。

资料缺失仍可读取最后真实结果并标日期；服务离线先按[部署维护](../../DEPLOYMENT.md)核对实例。备份包含库和文件证据，恢复到新目录。新源码落盘不等于服务已重新加载；不覆盖现有配置或数据。

授权改变策略、来源、存储、运行或协作边界时，同步对应现状及[项目综述](PROJECT_OVERVIEW.md)。没有自动综述维护或已验证的新模型会话加载流程。过去机器路径、端口、PID与逐轮测试记录可从[原协议的固定Git版本](https://github.com/LiRongji1995/stockfish-qlib-quant-system/blob/16d2fb810c7c921f55cd9b3f2f730627faec0d35/stock-fish/docs/archive/before-cleanup-20261005/stock-fish/docs/CODEX_DAILY_RESEARCH.md)追溯，不能据此推断当前实例。
