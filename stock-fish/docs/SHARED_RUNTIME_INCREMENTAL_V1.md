# 共享运行环境与有界增量 V1

2026-10-25，延续共享聊天入口工程。目标是恢复一个固定环境，先减少重复传输和计算，保持原策略、历史证据与来源鉴证。运行数据位于源码目录之外；没有复制业务数据库、全量行情或冻结源码，也不启动 HTTP 服务。

## 环境恢复与容量

`restore_shared_runtime.py` 使用已有 daily/review 的 58 包官方哈希锁。限定原生 macOS x86_64、CPython 3.12；不修改原 bootstrap、锁文件、pyqlib 或相邻 Qlib。显式缓存目录只按目标 SHA 查找所需工件；未命中才向原锁定的官方 HTTPS 地址下载，无自动重试。安装先暂存并验哈希，再离线安装，最后调用原环境验证器。

默认新增 HTTP body 上限160 MiB、单件48 MiB、恢复目录1 GiB、磁盘至少保留10 GiB；安装临时文件留在恢复目录内，完成后只移除本次拥有的暂存工件。返回 body 字节不等于 TLS 网络流量；250ms磁盘监测和准入也不是文件系统硬配额。失败环境和失败收据保留，普通命令不接管已有目录。

共享登记仍由 `codex_chat.py runtime-register` 完成。私有配置记录环境、原源码、state/cache、报告与预算；所有聊天使用同一默认登记。环境恢复成功不代表行情就绪、来源完整或投资策略有效。

## 新增入口

全局 `--runtime` 参数在子命令之前；使用已经登记的解释器和源码。用户继续在聊天中提出任务，以下命令是 Codex 的工程入口：

```sh
python scripts/codex_chat.py runtime-status
python scripts/codex_chat.py storage-status
python scripts/codex_chat.py --runtime shared-daily market-plan \
  --codes sh.600000 sz.000001 --sessions 2026-10-21 2026-10-22 2026-10-23
python scripts/codex_chat.py --runtime shared-daily market-sync \
  --codes sh.600000 sz.000001 --sessions 2026-10-21 2026-10-22 2026-10-23 \
  --calendar-record PRIVATE_ORIGINAL_CALENDAR_METADATA.json
python scripts/codex_chat.py --runtime shared-daily core-run \
  --manifest PRIVATE_CORE_REQUEST.json
```

日期仅演示语法。plan依据项目登记日历与实际收市时钟检查；sync还完整验证同一cache中的原始日历。`market-plan` 只盘点元数据，不将索引存在视为完整行情。`market-sync` 使用原 `CaptureCache` 和 SDK worker，固定写入已登记 state 下原有 `cache/`；不另建行数据库。先逐证券、逐交易日检查稳定 RAW 身份和已有原范围；全部验真后，将同一天确实缺失的证券合为一个原始请求，已有证券不再拉取。已有空响应、失败或PARTIAL保持未知且不自动重提。当前试点最多2只主板证券、3个已收盘交易日，最终批量路径最多3个请求、12次SDK调用；原硬额度仍为6个请求、18次SDK、180秒、32 MiB共享缓存总量和128 MiB采集读取量，私有配置更低时继续收紧。

采集前验证共享缓存中的原日历、完整自然日覆盖和请求身份；RAW行情要求原 `adjustflag=3`。空行、失败、部分数据和缺口保留 UNKNOWN，未完成请求不自动重试。没有精确分片时，完整验证已有宽范围history原请求和实际行，再引用原整份receipt生成只读行视图；不生成新的窄分片RAW/result/index。多父目标RAW行不一致即拒绝，缺实际行保持UNKNOWN。原范围的失败或未完成尝试不能靠缩小请求范围自动重试。试点不是全市场默认采集器，不能据此声称旧67日冷启动或完整因子历史已经优化完成。

`core-run` 的输入为 `CODEX_FROZEN_CORE_REQUEST_V1`，包含原 CaptureCache metadata 列表、观察日、目标交易日、带时区截止与覆盖类型。首次调用原 `run_core` 和原 owner.validate，保留全部八个原产物。相同来源、配置、源码与截止再次请求时，完整重验 SHA、七字段物理身份、原summary和原产物，再读取同一结果；不运行第二次 normalizer/selector，不写第二套大输出。

归档复用不恢复 live owner 或来源能力，不自动接入主题、新闻或新的业务日。原 R2 内部的 R1 对照和未知保留；DAILY_V1仍单独报告未执行，初始参数尚未验证，`MARKET_EDGE=NOT_ESTABLISHED`。全盘前流程仍用原 `premarket` 入口及其原完整性要求。

## 测量口径

新增逻辑字节、分配块和真正可释放空间分别报告。原SDK没有网络字节计数，因此只报告实际请求、实际来源行、归档增长和墙钟，不能把本地JSON体积称作网络下载量。一次性环境成本与每次行情/计算成本分别记账。真实小样本、TEST_FIXTURE和完整盘前生产性能分别验收；不将少量样本外推为全市场收益。

## 本机真实验收

共享环境已登记为默认 `shared-daily`，使用已发布检出的原核心源码，数据、报告和环境均在固定私有目录。58个锁定包全部从本机缓存按官方SHA复用，网络下载0字节、0请求；原 pip check、安装身份、rules/daily/review doctor、应用/CLI/隔离SQLite烟测六步均退出0。环境最终306,320,816逻辑字节（约292 MiB）、331,083,776分配字节；恢复过程峰值373,416,187逻辑字节。含首次失败共242.196秒，这是一次性安装开销。

首次恢复因pip临时pyc在扫描中消失而退出1；已修复子文件ENOENT竞态并补回归。原失败收据保持，随后只修复本次拥有的同一环境，离线完成并另存恢复收据；没有复制另一套环境。约11.1MB本次卸载残留被保留，未计作已释放空间。当前私有容量配置为环境与数据合计1 GiB逻辑上限、最少10 GiB磁盘余量；原盘前配置缓存64 MiB，增量入口进一步限制为有效32 MiB缓存上限；核心输出32 MiB，总量与worker预算均不自动提高。

真实样本来自原 Baostock worker：186个自然日日历完整返回，沪深各1只证券的2026-10-21至23日行情共6行。随后为范围复用增加10月20日至21日的小批次4行，最终版本补取10月19日两证券共2行；整个测试只有2只证券、5个不同交易日的RAW。未下载全市场历史、模型或因子长历史。
