# 证据日志 V2 隔离原型

`EXACT_EVIDENCE_ROW_AUDIT_JOINT_SPOOL_V2` 仅是显式数学与存储原型。现有
`evidence_audit_spool.py`、题材计算、行情 reader、来源发行器、生产入口和策略配置均未切换。
本原型不抓取数据、不读业务数据库、不发行行情来源能力，也不重试既有失败运行。

## 要解决的具体问题

V1 的成功路径分别在封存、规范依赖迭代和审计清单生成时整读日志；后者又有两次完整文件验证。
V2 的联合操作把规范依赖哈希与清单放在同一个内部只读验证过程：完整 pre 验证、排序后的规范记录迭代、完整 post 验证。
它减少重复读取，保留全部行与所有完整性判断。真实大范围运行能否满足既有预算仍未验证，不能引用隔离测试声称原生题材计算或全局4GiB预算通过。

## 写入与封存证据

- 每个唯一证据行继续保存完整规范 JSON、换行和 SHA；重复行继续从真实磁盘读取、核 SHA 并比较内容，没有 LRU。
- 写入时同步维护文件字节数、预期 SHA、原始 inode/设备/模式、每行位置及插入顺序。封存前的实际字节必须匹配这个写入账本；把已经损坏的关闭状态重新计算 SHA 不能授予权限。
- 完整扫描逐行验证 index 的规范 JSON、精确字段、整数位置、唯一顺序和全量覆盖；行段验证规范 JSON、SHA、换行、连续 offset、行数及全部字节覆盖。额外文件、截断、空洞或重复位置拒绝。
- 实际文件每次读取均核 regular file、单链接、原始文件身份以及读取前后的完整7项 FP。使用 `O_NOFOLLOW`、`O_NONBLOCK` 与 `lstat/fstat`，symlink/FIFO 在可能阻塞的读取之前拒绝。
- 联合操作对所有数据文件做 pre/post 整 SHA 和完整7FP；manifest 自身也按写入账本整读验证。相同大小、恢复 mtime 的修改仍被 SHA、ctime 或身份守卫拒绝。

7FP 为设备、inode、模式、大小、mtime_ns、ctime_ns、flags。初次封存绑定当时实际 FP；后续变化不能静默刷新。文件不得由旧 manifest、JSON 中的 `verified` 或 caller validator 恢复能力。

## 显式接口

`SpoolingEvidenceResolverV2` 继承原 `EvidenceResolver` 的可见性、资格、时钟及父来源决策。
`joint_dependency_digest_and_audit_manifest()` 不接受外部验证对象，只在当前 resolver 所拥有的真实日志上执行，返回规范依赖哈希与清单副本。
哈希仍由原 `digest_json_stream` 产生，依赖来源和记录排序与原 resolver 相同。

普通 `effective_dependencies()` 的规范记录访问也执行完整前后认证，不能依赖联合结果的缓存。
流式扫描和联合迭代只保留一行；行段和单行不超过32MiB。索引与记录位置仍在内存中。
显式 `list(records)` 或切片是 caller 请求的结果物化，不属于流式内存保证。

`read_metrics` 记录本实现显式读取实际返回的字节与调用次数，包括失败前已经返回的字节；它不是全部内核、行情来源或生产 worker I/O 计量。
隔离测试比较 V1 的 `close + digest + audit_manifest` 与 V2 联合操作的实际读取量，不以文件大小或耗时冒充计量结果。

## 失败与范围

完整性异常使用专用 `RuntimeError` 子类，不被证据格式的 `ValueError` 捕获成普通 UNKNOWN。
失败保留原始文件；清理关闭写句柄，主失败与清理失败分别记录，不删除、清空或重写失败日志。
保存 manifest 仅说明那次封存检查的结果，不能证明之后的联合操作成功。

读取过程中同时发生主失败和文件/目录终验失败时，保留原主异常并分别登记
`READER_PRIMARY` 与 `READER_CLEANUP`。读取结束后还核父目录路径，防止中途引入目录别名。
一个writer关闭失败时仍尝试关闭另一writer，不以第一个清理异常跳过剩余句柄。
普通记录索引、普通流式迭代和manifest写入同样保留原主异常；对应的
`ORDINARY_ACCESS/ORDINARY_ITERATION/PUBLISH` 的 `PRIMARY`、`CLEANUP` 分别登记。
后置完整验证仍执行，其失败不能改写先发生的预算、读写或fsync失败；没有主失败时仍抛终验或关闭异常。

本轮只验证 `TEST_FIXTURE` 下决策、全部规范行、依赖哈希、分段、真实篡改拒绝及计量。
尚未验证真实全市场、年度研究、来源消费者接线、并发服务或投资有效性。
本原型没有扩大输出或读取预算，没有修改任何策略公式、阈值、窗口、资格或旧 run。

## 隔离验证

2026-10-12 使用已固定的项目 Python（`-B`），以独立 `TemporaryDirectory` 和
`TEST_FIXTURE` 执行本文件对应31项新测试及V1的7项定向测试：38项通过，pytest退出码0，
实际测试2.19秒，整个监督入口4.16秒，子进程峰值RSS为42,389,504字节，DB/网络尝试均为0。
pytest仅借用已有纯Python依赖目录；Pydantic与其native core仍来自固定运行环境，没有安装依赖。
临时夹具在子进程退出后删除，原真实研究和失败证据未清理。

测试子进程2.82秒、外层4.19秒，OS峰值42,881,024字节，DB/网络尝试0。
