# 主题流 V3：完整压缩日志与实际逻辑读取计量

本版是显式的新研究执行入口 `theme_evolution_streaming_v3.py`，使用当前进程拥有的
`evidence_audit_spool_v3.py`。原数值配置、题材状态机、成员及时点、缺日、价格和风险语义
来自冻结 V1 helpers；完整逐会话 for-loop 与 V2 相同。旧 V1/V2、旧 run、默认 CLI 和服务保持原身份。

## 完整审计

全部 allowed evidence 原记录仍写入日志，不过滤成员、去除证据或缓存重复访问。
V3 以独立 gzip frame 保存每条完整原记录；写入时保存逻辑 SHA/长度与实际 frame SHA/长度、
连续物理偏移的 owned 账本。每次普通读取仍由真实文件返回完整记录，验证 frame、CRC、EOF、
尾部、换行、逻辑 SHA 和规范 JSON。不能以目录或 manifest 重新构造 owner 权限。

联合审计保持完整 pre、canonical 和 post。pre/post 扫描所有压缩段、完整索引和清单，
核对整 SHA、七字段、实际写入账本及全部行的偏移覆盖。canonical pass 按原依赖顺序解码每一条
完整原记录并验证全部逻辑内容；依赖 hash 与旧执行相同。物理 seal 本身不证明完整逻辑解码成功，
只有全部 canonical 消费及 post 完成后才能声明 `complete_allowed_row_audit`。

## 计量与来源边界

非 `TEST_FIXTURE` 输入必须提供真实 `_logical_read_callback(bytes)`，直接传入 resolver，
在每个实际返回的非空解码块上调用并计入 caller 的既定 returned-read budget；本地调用数还记录空块。
fixture 可以省略并查看本地实际计量，
传入非 callable 会被拒绝。callback 只计量，不能授予来源、owner、原件或参数验证能力。

压缩物理读取仍由 caller 原有真实读句柄计量；逻辑解码返回另行计量，因此不能只统计压缩大小。
日志指标单列物理与逻辑读取，不能把它们冒充完整 worker、内核或全市场 I/O。
预算异常须保留原异常对象，穿过 evidence envelope 的格式错误处理；不能变为 UNKNOWN。
失败 partial 日志、primary 与 cleanup 分开保存，不用后来恢复的 JSON 标记成功。

仍要求真实 `SourceMarketStream` 和 live `_source_terminal_validator()`。联合审计后核原 input、
descriptor、源码身份，再执行 caller 当前 owned 原件终验及再次绑定。
模块不独立认证 caller closure 的 owner，输出明确由外层完成完整来源认证。
真实 caller 在输出 gzip 完整 CRC/EOF 检查后，还必须再次完成全部原件、源码、原 run/input/导出
及控制的外层终验；内部 callback 完成不能代替这一步。
