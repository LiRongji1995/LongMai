## 当前行为

运行登记和文件引用不再把保存的设备号、inode、mtime、ctime 当作准入条件。同一路径的同字节文件重新复制、恢复或替换后，不需要恢复原来的文件系统身份。

文件按实际 SHA-256 和字节数校验，已有引用、RAW、回执、导出与本地 HMAC 原文不重写。旧 `fp` 字段可以继续读取，属于历史兼容元数据；仅有文件大小或目录清单不能证明内容正确，也不能获得市场来源能力。内容改变仍拒绝；文件不存在、类型错误、读到半份内容仍报错。

证券代码与交易所、观察日和目标日、原始资料可见时间、来源窗及完整性、策略内容版本、正式排序和 UNKNOWN 语义保持。网页/API token、Host/Origin 与本地访问规则不属于本次删除范围。

## 旧登记和失败记录

旧登记的 `binding` 不批量改写。它原来用于计算的 scope 和 operations 位置作为稳定的历史账本编号继续使用，不再与本机 stat 比较。旧锁继续使用，并增加路径资源锁，避免设备号变化后将同一目录拆成两份任务。

同路径的新登记复用旧账本和预算；存在多份旧账本而无法唯一对应时，不自动挑选或丢弃记录。失败、不明、SUBMITTING 和来源请求范围继续对账，换 key、版本或 engine 不构成重试授权。

业务控制库按 workspace 与账本内容识别，不再强制原 `original_carrier` 的设备号和 inode。一次正在进行的 SQLite 事务、OS 锁、原子写或删除中仍保留必要的对象一致性检查，防止把提交、解锁、删除或进程回收作用到另一个对象。这些检查不构成跨运行的机器登记门禁。
