# Go 主系统与 SQLite V2 重建

本轮基线为 `1ceb256e5331ec24ca9a5bb4185c52ebbdba4245`，在现有 `review` 分支实施；起始工作区干净，远端 main 只读核验相同。用户后续明确授权完成检查后直接提交并推送远端 main；仍不切分支、不覆盖发布检出、不切换生产。最终验收状态见 VALIDATION.md，真实数据与日志留在私有 reports 目录。

## 边界

采用模块化单体。`domain/contracts` 保存身份、精确值和生命周期合同；`evidence` 负责严格输入及来源选择；`facts` 只计算公共事实；`strategies/r1` 与 `strategies/v2` 独立消费事实。`application` 通过 `ports` 编排导入、研究、查询、任务及发布。`infrastructure` 实现新 SQLite、旧库只读历史、资源和文件。`interfaces` 提供同一个应用服务的 CLI/HTTP 外壳。`core` 仅保留旧诊断兼容入口，不能成为新系统的单体规则容器。

生产主动身份保持 `STAGE_AWARE_MOMENTUM_V2`；R1 必须显式选择 `STAGE_AWARE_RESEARCH_R1`、`RESEARCH_ONLY`、`production_promotion=DISABLED`。`go-core` 原影子验证调用链保留；本次不创建第三套策略实现。Python SDK 和 Qlib/旧冻结模块保留原入口，Go 不调用 Python 策略解释器。

## 数据映射

| 旧权威能力 | 新库职责 | 验收 |
|---|---|---|
| documents 中冻结输入、配置、来源、历史/结果描述 | 原字节证据与稳定旧 ID 映射；类型化快照和结果头 | 原字节逐项 hash、身份集合、外部引用 |
| history_evidence_rows | 不可变证据对象与精确 TEXT 行情/来源投影 | 全量 hash、投影重建、修订与时钟 |
| history_partition_members | 紧凑内部键及分区成员关系 | 全量成员集合、分区哈希、LEFT JOIN 缺失检查 |
| 原任务和事件 | 只读历史归档；新任务与事件事务 | 旧 QUEUED/RUNNING 不恢复执行 |
| 运行元数据、逐股明细与公共证据 | 独立结果头/明细、未发布暂存、最终 manifest | 重启读取、查询与导出同源、篡改拒绝 |
| 派生缓存 | 可删除、版本/全部依赖入键、有容量上限 | 冷暖/时点/修订/损坏/清理重建一致 |
| 其他旧表/namespace | 逐项识别并原字节归档；不能静默跳过 | 清单、全量键集合；有效未支持则阻塞完成 |

迁移流程固定为 plan → 原生 SQLite 一致性 backup → 新目录 initialize → 分批 migrate/resume → 全量 verify → publish。检查点与目标批次同事务。只能接续同一冻结源身份；幂等使用同键同内容校验，异内容必须报冲突。

## 应用发布与运行

应用只从 V2 库读取；旧适配只用于显式迁移和对照。导入、结果与迁移分别具有最终发布边界。任务是可变状态，事实和已发布结果追加只读。中断恢复记录为 INTERRUPTED，显式恢复创建新尝试并保留事件。隔离 scheduler 默认暂停。

HTTP 默认回环绑定；写入需要 bearer 凭据；请求仅接受已登记输入身份，不接受任意文件路径。CLI 与 HTTP 共用应用服务和任务状态。健康探针仅做轻量连通/schema 检查，深度验证为显式命令。

## 预算和切换

真实全池最多 6 次、单次 1800 秒、累计 10800 秒，按策略单独计次且串行。快照/迁移/验证/恢复累计 7200 秒；新增持久文件上限 50GiB，始终保留 10GiB 可用空间。研究默认 300 秒，payload 2GiB，RSS 1GiB；迁移按盘点体量流式处理，不套研究 payload 限额。

只演练本任务隔离实例。切换要求发布验证摘要、schema、单写者、默认策略、任务和增量检查。切换后新写入保留变更账本；回滚必须导出/验证可重放部分，不能通过删除新写入假装无损。不能兼容旧系统的记录使自动回退阻塞，V2 数据继续保留。

### 批次投影与运行进度

冻结批次的题材成员、资金及来源范围使用独立版本化类型表；老 snapshot 与新 app input 共用原始字节绑定和重建验证。发布前需要基础迁移和批次投影两道门禁。批次投影的版本、DDL hash 和当前清单身份进入研究 manifest，路径不进入可移植身份。

工作进度经应用端口同步保存，阶段变化、每100只或5秒生成有界事务中的进度事件；终态不能被迟到进度复活。失败保留最近已保存进度。RSS/输入/输出预算通过 context 取消 SQL 时保留真实预算原因，避免误记为用户取消。
